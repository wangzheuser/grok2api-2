# Grok2API 生产环境 Docker 部署规范

## 1. 适用范围

本文档规定 Grok2API 生产环境的 Docker 部署、更新、验证和回滚流程。
核心目标是在本地完成耗费 CPU 的镜像构建，生产服务器只负责导入镜像和运行容器。

涉及以下任务时，应先完整阅读本文档：

- 构建、导出、上传或导入生产镜像；
- 新建、更新、重启或回滚生产容器；
- 修改生产 Docker Compose 或运行环境配置；
- 同步 `.env`、数据目录、数据库或其他持久化内容；
- 执行部署健康检查或故障恢复。

本文档只保存稳定流程和非敏感变量名。服务器地址、SSH 凭据、后台密码、代理凭据、
数据库连接串和其他秘密均由本机受控配置或运行环境管理。

## 2. 强制部署链路

生产部署采用以下固定链路：

```text
当前本地工作区
  → 本地构建 linux/amd64 镜像
  → 验证镜像平台和标签
  → 导出镜像归档并计算 SHA-256
  → 上传镜像归档和必要的部署文件
  → 服务器校验 SHA-256
  → 服务器执行 docker load
  → 校验最终 Docker Compose 配置
  → 使用 --no-build 启动容器
  → 执行健康、认证、日志和业务状态检查
  → 记录非敏感部署状态并清理临时归档
```

生产服务器只负责加载镜像和运行容器，不执行以下操作：

- `docker build`；
- `docker buildx build`；
- `docker compose build`；
- 任何会在生产服务器触发镜像构建的等价操作。

即使仓库中存在 `Dockerfile`，它也仅作为本地镜像构建输入。生产 Compose 中的应用服务
必须引用已经导入的镜像标签，并且最终生效配置不得包含应用服务的 `build:`。

## 3. 敏感信息边界

### 3.1 后台密码

后台登录密码只从本地 `.env` 的 `GROK_APP_APP_KEY` 获取。部署过程遵循以下规则：

- 只检查变量是否存在和是否为空，不输出变量值；
- 不打印、复制或展示完整 `.env`；
- 不把密码放入命令行参数、镜像标签、归档文件名或部署状态文件；
- `.env` 不进入 Docker 构建上下文，也不打包进镜像；
- 服务器上的 `.env` 应限制为仅部署账号可读写；
- 后台认证检查只记录 HTTP 状态码和通过结果。

### 3.2 仓库中不得记录的内容

- 服务器地址、SSH 端口、登录账号或认证凭据；
- 私钥内容和本机私钥绝对路径；
- `GROK_APP_APP_KEY` 的实际值；
- 代理 URL、代理账号、代理密码或生产代理节点清单；
- 数据库、Redis 或其他基础设施连接串；
- Token、Cookie、Cloudflare Clearance 或同类认证材料；
- 某次部署产生的容器 ID、归档路径或其他短期状态。

服务器连接信息从本机受控配置按需读取。部署回复和服务器状态文件只记录经过脱敏的结果。

## 4. 部署前门禁

### 4.1 本地代码状态

构建前记录以下非敏感信息：

- 当前分支；
- Git HEAD 短哈希；
- 工作区是否包含未提交修改；
- 镜像标签；
- 构建时间；
- 目标平台。

镜像内容以当前本地工作区快照为准。工作区存在未提交修改时，部署结果应明确标记
`dirty=true`，避免把线上镜像误认为只对应 Git HEAD。部署任务不隐式执行 `git add`、
`git commit` 或 `git push`。

### 4.2 本地质量检查

根据本次修改范围执行相关自动化测试。项目完整代理功能变更的推荐门禁为：

```bash
ruff check app tests
python -m unittest discover -s tests -p "test_*.py"
git diff --check
```

部署已有镜像时，至少确认该镜像对应的测试结果和源代码状态可追溯。

### 4.3 构建上下文检查

本地构建前复核 `.dockerignore`，至少确保以下内容不进入构建上下文：

- `.env` 和其他本地秘密文件；
- `.git`；
- `data/`；
- `logs/`；
- 本地数据库、缓存和临时文件。

### 4.4 生产环境检查

执行远程变更前检查并记录：

- Docker 与 Docker Compose 是否可用；
- 目标端口是否已被其他服务占用；
- 当前容器和健康状态；
- 当前应用镜像标签与镜像 ID；
- 持久化目录和外部存储状态；
- 上一个可回滚镜像标签；
- 最终 Compose 配置是否只包含 `image:`，且应用服务没有有效 `build:`。

上传文件、修改生产配置、替换容器、调整权限或操作生产数据前，按照项目危险操作规范
取得用户明确确认。

## 5. 本地构建镜像

### 5.1 镜像标签

本次上传镜像使用不可变标签。标签应包含 Git 短哈希或 UTC 构建时间，避免仅用 `latest`
表示具体发布版本。

示例变量：

```bash
SOURCE_REV="$(git rev-parse --short HEAD)"
BUILD_TIMESTAMP="$(date -u +%Y%m%d%H%M%S)"
IMAGE_TAG="grok2api:${SOURCE_REV}-${BUILD_TIMESTAMP}"
```

变量值只用于当前部署，不把某次实际值写入本文档。

### 5.2 构建命令

在项目根目录执行本地跨平台构建：

```bash
docker buildx build \
  --platform "linux/amd64" \
  --load \
  --tag "${IMAGE_TAG}" \
  .
```

构建结束后验证镜像存在，并确认操作系统和架构分别为 `linux`、`amd64`：

```bash
docker image inspect "${IMAGE_TAG}" \
  --format '{{.Id}} {{.Os}}/{{.Architecture}}'
```

只有镜像标签、镜像 ID和平台均符合预期时，才进入导出阶段。

## 6. 镜像导出、上传与导入

### 6.1 本地导出

使用只包含非敏感标识的临时路径导出镜像：

```bash
IMAGE_ARCHIVE="${TMPDIR:-/tmp}/grok2api-image.tar"
docker save --output "${IMAGE_ARCHIVE}" "${IMAGE_TAG}"
shasum -a 256 "${IMAGE_ARCHIVE}"
```

记录本地归档 SHA-256。归档文件不得包含 `.env`、数据库备份或其他运行时秘密。

### 6.2 上传与摘要校验

通过本机已有的受控连接配置上传归档，不在仓库文档或命令模板中固化服务器地址和凭据。
上传完成后，在服务器计算同一归档的 SHA-256，并与本地结果逐字比较。

摘要不一致时停止部署，重新传输并再次校验。

### 6.3 服务器导入

摘要一致后，服务器只执行镜像导入：

```bash
docker load --input "${IMAGE_ARCHIVE}"
docker image inspect "${IMAGE_TAG}" \
  --format '{{.Id}} {{.Os}}/{{.Architecture}}'
```

确认导入镜像为 `linux/amd64`，并记录非敏感的镜像标签和镜像 ID。目标镜像未成功导入时
停止部署，不切换为服务器构建。

## 7. Docker Compose 配置

### 7.1 应用镜像

服务器最终 Compose 配置中的应用服务必须引用本次导入的镜像标签。应用服务不得设置
有效的 `build:`。如使用环境变量传入镜像标签，应先渲染并核对最终配置。

### 7.2 配置校验

启动前执行：

```bash
docker compose --env-file ".env" config --quiet
docker compose --env-file ".env" config
```

检查渲染结果：

- 应用服务的 `image` 指向本次导入的不可变标签；
- 应用服务不存在有效 `build`；
- 数据和日志目录继续使用持久化挂载；
- 环境变量名称符合预期；
- 输出中没有意外展开的秘密。

### 7.3 启动命令

统一使用：

```bash
docker compose --env-file ".env" up -d --no-build
```

`--no-build` 是生产启动的强制门禁。镜像缺失时应停止处理并检查上传或导入结果。

## 8. 运行数据保护

常规版本更新只替换应用镜像，保留服务器已有运行数据，包括但不限于：

- `data/`；
- `logs/`；
- `config.toml`；
- 账户数据库；
- 托管代理健康状态、账号绑定和共享任务状态；
- 外部 Redis、MySQL 或 PostgreSQL 数据。

首次部署需要初始化数据时，应先确认目标目录为空。后续部署不从本地覆盖服务器已有数据库
或运行配置。数据库迁移、配置覆盖、账户导入和批量数据更新属于独立操作，执行前应备份并
取得单独确认。

使用本地账户存储时，SQLite 文件必须位于持久化目录。使用外部存储时，镜像更新不得修改
或清空外部数据。删除或重建容器时，不删除持久化卷和宿主机数据目录。

## 9. 部署后验收

### 9.1 容器状态

检查 Compose 和容器状态：

```bash
docker compose --env-file ".env" ps
docker inspect "grok2api" \
  --format '{{.State.Status}} {{if .State.Health}}{{.State.Health.Status}}{{end}} {{.Image}}'
```

验收条件：

- 应用容器处于运行状态；
- 配置健康检查时，健康状态为 `healthy`；
- 实际容器镜像 ID与本次 `docker load` 导入的镜像一致；
- 重启策略符合生产配置。

### 9.2 健康接口

先从服务器内部访问：

```text
http://127.0.0.1:${SERVER_PORT}/health
```

再从本地工作站访问对外健康地址。两次请求都应返回 HTTP 200，并且响应体表示服务健康。
实际地址和端口从运行环境获取，不写入本文档。

### 9.3 后台认证

使用本地 `.env` 中的 `GROK_APP_APP_KEY` 验证后台接口：

- 正确值应通过认证；
- 使用明显错误的临时值应返回未认证状态；
- 只记录 HTTP 状态码和验证结论；
- 不输出、记录或持久化真实密码。

### 9.4 日志检查

检查本次启动日志，重点检索：

- `ERROR`；
- `CRITICAL`；
- `Traceback`；
- 未处理异常；
- 数据库或共享状态初始化失败；
- 配置解析失败。

日志检查通过后，还应确认服务没有持续重启或健康状态反复波动。

### 9.5 业务配置检查

镜像更新不得隐式改变实际业务出口。至少核对：

- 统一网络出口模式（直连、托管代理池或 Resin）；
- 托管节点数量、健康状态和账号绑定摘要；
- Resin URL 模板是否已配置且管理端仅显示脱敏值；
- 当前代理模式无可用出口时的失败关闭状态；
- 共享状态表或存储后端是否正常；
- 现有账户和运行配置是否完整。

### 9.6 服务器无构建检查

部署结束后确认：

- 最终 Compose 应用服务没有 `build`；
- 服务器不存在本次部署触发的 Docker BuildKit、`docker build` 或 `docker buildx` 进程；
- 容器使用的是上传并导入的镜像。

## 10. 部署状态记录

每次部署可以在服务器保存一份权限受控的状态文件，只记录以下非敏感元数据：

- 服务名；
- UTC 部署时间；
- 源分支和 Git 短哈希；
- 工作区是否为 dirty；
- 镜像标签和镜像 ID；
- 目标平台；
- Compose 项目标识；
- 健康检查结论；
- 上一个镜像标签；
- 使用本地构建、上传、`docker load` 和 `--no-build` 的事实；
- 启动、停止和回滚命令模板。

状态文件不保存服务器认证信息、后台密码、代理凭据、连接串、Token、Cookie 或 `.env` 内容。

## 11. 回滚

部署前保留上一个可用镜像标签、镜像 ID和有效 Compose 配置。新版本出现以下情况时，
使用上一镜像回滚：

- 容器启动失败或持续重启；
- 健康检查持续失败；
- 后台认证异常；
- 数据库或共享状态初始化异常；
- 关键业务路由与部署前配置不一致。

回滚步骤：

1. 将应用服务镜像恢复为上一可用标签；
2. 校验 Compose 最终配置；
3. 执行：

   ```bash
   docker compose --env-file ".env" up -d --no-build
   ```

4. 重新执行容器、健康接口、后台认证、日志和业务配置检查；
5. 记录回滚原因与结果。

回滚同样遵守服务器不构建镜像的规则。回滚时不删除或覆盖持久化数据。

## 12. 清理规则

部署验证通过后：

- 删除本地和服务器上的临时镜像归档；
- 删除为上传创建的非必要临时目录；
- 保留当前版本和上一可用版本镜像；
- 清理更旧镜像前确认没有容器引用，并按危险操作规范取得确认；
- 保留必要的非敏感部署状态和故障审计记录；
- 再次确认 `.env`、数据库备份和其他秘密文件权限符合预期。

## 13. 最终验收清单

- [ ] 本地工作区状态和测试结果已记录；
- [ ] 镜像在本地构建，平台为 `linux/amd64`；
- [ ] 镜像归档上传前后 SHA-256 一致；
- [ ] 服务器通过 `docker load` 导入镜像；
- [ ] 最终 Compose 应用服务没有有效 `build:`；
- [ ] 服务通过 `docker compose --env-file .env up -d --no-build` 启动；
- [ ] 容器镜像 ID与导入镜像一致；
- [ ] 内部和外部健康检查均通过；
- [ ] 后台正确凭据通过、错误测试值被拒绝，且真实密码没有回显；
- [ ] 启动日志没有关键异常；
- [ ] 统一代理出口模式、托管库存和 Resin 配置保持预期；
- [ ] 服务器没有执行或遗留 Docker 构建任务；
- [ ] 持久化数据和运行配置保持完整；
- [ ] 回滚镜像与回滚方法已经记录；
- [ ] 临时镜像归档已经清理。
